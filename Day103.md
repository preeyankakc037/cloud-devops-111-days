# Day 103 – Introduction to Cloud IAM (Identity & Access Management)

## Overview  
Today I started learning about Identity and Access Management (IAM), one of the most important concepts in cloud computing. After working with Kubernetes, I wanted to understand how access and permissions are controlled in cloud platforms.

## My Understanding  
I realized that IAM is all about **who can do what** in a cloud environment.

Instead of giving full access to everyone, cloud platforms allow us to:
- Assign specific permissions
- Control access to resources
- Improve security by following the principle of least privilege

IAM ensures that users and services only have the access they actually need.

## What I Did  

I explored the basic components of IAM such as users, roles, and policies. I understood how permissions are attached to roles and then assigned to users or services.

I also looked at how cloud providers structure access control and how important it is to avoid using root/admin access for daily tasks.

## Key Concepts  

Users  
Individuals or services that need access to cloud resources.

Roles  
A collection of permissions that define what actions are allowed.

Policies  
Rules that specify permissions (what is allowed or denied).

Principle of Least Privilege  
Grant only the minimum permissions required to perform a task.

## Example Scenario  

Instead of giving a developer full admin access:  
- Create a role with limited permissions (e.g., only access to storage or compute)  
- Assign that role to the developer  

This improves security and reduces risk.

## Commands / Practice (Generic)  

- Create a user  
- Create a role  
- Attach policy to role  
- Assign role to user  

## Key Takeaway  

IAM is the foundation of cloud security.  
Understanding it properly is critical before working with any cloud services.
