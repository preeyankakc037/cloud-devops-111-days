# Day 105 – AWS CloudFormation (Infrastructure as Code in Practice)

## Overview  
Today I explored AWS CloudFormation as a real-world implementation of Infrastructure as Code (IaC). Instead of manually creating resources, I learned how to define and deploy infrastructure using templates.

## My Understanding  
CloudFormation allows us to describe infrastructure in a declarative way using YAML or JSON. Instead of executing step-by-step commands, we define the desired state, and AWS takes care of provisioning and managing resources.

This approach improves:
- Consistency  
- Repeatability  
- Automation  

## What I Did  

I studied how CloudFormation templates are structured and how different components like resources, parameters, and outputs work together.

I also understood how a **stack** acts as a single unit to manage multiple resources, making deployments easier to control and update.

## Key Concepts  

CloudFormation Template  
A YAML/JSON file that defines infrastructure.

Stack  
A collection of resources managed together.

Resources  
Actual AWS services like EC2, S3 defined in the template.

Parameters  
Inputs to make templates reusable and dynamic.

Outputs  
Values returned after deployment (like IP, URLs).

## Steps I Learned  

- Define resources in a template  
- Add parameters for flexibility  
- Create a stack using the template  
- Monitor stack creation  
- Debug errors using events  
- Update stack when needed  

## Key Insight  

Instead of manually configuring infrastructure, everything can be:
**Version-controlled + Automated + Reproducible**

## Reflection  

This felt like a major shift from manual cloud usage to real DevOps practices. CloudFormation brings the same discipline of coding into infrastructure management.
