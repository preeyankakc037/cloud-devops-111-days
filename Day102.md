# Day 102 – Kubernetes Volumes & Persistent Storage

## Overview  
Today I learned how Kubernetes handles data storage. Until now, most of my work was with stateless applications, but I realized that real-world apps often need to store data persistently.

## My Understanding  
I understood that containers are ephemeral—when a pod is deleted, all its data is lost. To solve this, Kubernetes provides volumes and persistent storage options so data can survive beyond the lifecycle of a pod.

## What I Did  

I explored different types of volumes in Kubernetes and how they are mounted inside containers. I learned the difference between temporary storage and persistent storage.

I also studied how Persistent Volumes (PV) and Persistent Volume Claims (PVC) work together to provide storage in a more flexible and scalable way.

## Key Concepts  

Volumes  
Storage that is attached to a pod and exists as long as the pod is running.

Persistent Volume (PV)  
A piece of storage in the cluster that has been provisioned.

Persistent Volume Claim (PVC)  
A request for storage by a user, which Kubernetes fulfills using available PVs.

## Example YAML  

### Persistent Volume
```yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: my-pv
spec:
  capacity:
    storage: 1Gi
  accessModes:
    - ReadWriteOnce
  hostPath:
    path: /data


## Persistent Volume Claim
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-pvc
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 500Mi


## Pod using PVC

apiVersion: v1
kind: Pod
metadata:
  name: storage-pod
spec:
  containers:
  - name: app
    image: nginx
    volumeMounts:
    - mountPath: "/usr/share/nginx/html"
      name: storage
  volumes:
  - name: storage
    persistentVolumeClaim:
      claimName: my-pvc

```

## Reflection

This was an important topic because most real applications (databases, file storage systems) require persistent data. Understanding PVs and PVCs made Kubernetes feel more practical and production-ready.
