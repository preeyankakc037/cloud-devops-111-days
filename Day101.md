# Day 101 – Kubernetes ConfigMaps & Secrets

## Overview  
Today I learned how to manage application configuration in Kubernetes using ConfigMaps and Secrets. After completing 100 days and reflecting on my journey, I wanted to dive deeper into how real-world applications handle environment-specific settings and sensitive data.

## My Understanding  
I realized that hardcoding configuration values inside applications is not a good practice. Applications often need different configurations for development, testing, and production environments.

Kubernetes provides:
- **ConfigMaps** → for non-sensitive data (like environment variables, config files)
- **Secrets** → for sensitive data (like passwords, API keys, tokens)

This separation makes applications more secure and flexible.

## ConfigMaps  
ConfigMaps are used to store plain configuration data.

### Example ConfigMap
```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  APP_ENV: production
  APP_DEBUG: "false"
