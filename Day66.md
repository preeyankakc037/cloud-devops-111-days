# Day 66 – Infrastructure as Code

## Overview

Today I moved into Infrastructure as Code. Until now I was deploying and managing things manually or through the console, but today I understood how infrastructure can be defined and managed using code.

## My Understanding

I realized that setting up servers, networks, and services manually is not practical in real environments. It takes time and is prone to mistakes. With Infrastructure as Code, I can define everything in a file and recreate the same setup anytime.

## What I Learned

Instead of clicking around in the cloud console, I can write configuration files that describe my infrastructure. These files can be version controlled, shared, and reused just like application code.

## Key Concepts

**Infrastructure as Code**
It means managing infrastructure using code files instead of manual processes. This makes everything consistent and repeatable.

**Declarative Approach**
I define what I want, and the tool takes care of creating it. I do not need to worry about each step.

**Tools**
I came across tools like Terraform and CloudFormation that help in writing and managing infrastructure.

## Realization

Earlier I thought creating resources manually was fine for learning, but now I see that real systems need automation. Infrastructure should be easy to recreate, scale, and manage without depending on manual steps.

## Summary

Today I understood that Infrastructure as Code is a major step in DevOps. It brings consistency, reduces errors, and makes infrastructure management much more efficient.
