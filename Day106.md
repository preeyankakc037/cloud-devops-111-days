# Day 106 – Terraform Basics (Multi-Cloud Infrastructure as Code)

## Overview  
Today I started learning Terraform, a widely used Infrastructure as Code (IaC) tool. After working with AWS CloudFormation, I wanted to understand how Terraform differs and why it is preferred in many real-world scenarios.

## My Understanding  
Terraform allows us to define infrastructure using code, similar to CloudFormation, but with one major advantage—it is **cloud-agnostic**.

This means:
- It works across AWS, Azure, GCP  
- It is not limited to a single provider  
- It provides flexibility in multi-cloud environments  

## What I Did  

I explored how Terraform configurations are written using HCL (HashiCorp Configuration Language). I understood how providers, resources, and variables are defined.

I also studied the Terraform workflow and how it manages infrastructure lifecycle step by step.

## Key Concepts  

Terraform  
An open-source IaC tool used to provision and manage infrastructure.

Providers  
Plugins that allow Terraform to interact with cloud platforms (AWS, Azure, etc.).

Resources  
Infrastructure components like EC2, S3 defined in code.

State File  
Keeps track of current infrastructure so Terraform knows what to change.

Execution Plan  
Preview of changes before applying them.

## Terraform Workflow  

1. Write configuration files  
2. Initialize Terraform (terraform init)  
3. Preview changes (terraform plan)  
4. Apply changes (terraform apply)  
5. Destroy resources if needed (terraform destroy)  

## Key Insight  

Terraform introduces a powerful concept:
**Plan before Apply**

This ensures:
- No unexpected changes  
- Better control over infrastructure updates  

## Reflection  

Compared to CloudFormation, Terraform feels more flexible and widely used in industry. The idea of managing infrastructure across multiple cloud providers using one tool is very powerful.
