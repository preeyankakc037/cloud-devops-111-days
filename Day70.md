# Day 70 – Introduction to Containers and Docker

## Overview

Today I moved into containers, which is something I kept hearing about in DevOps. I finally understood why containers are so important and how they solve real problems in development and deployment.

## My Understanding

Earlier, when I ran applications, they depended on my system setup. Sometimes code worked on my machine but failed somewhere else. Today I understood that containers solve this issue by packaging everything the application needs.

## What I Learned

A container includes the application, its dependencies, libraries, and configurations. This means I can run the same container anywhere and expect the same result.

## Key Concepts

**Containers**
They are lightweight environments that run applications in isolation. They are faster and more efficient compared to virtual machines.

**Docker**
Docker is the tool used to create and manage containers. It allows me to build images and run them as containers.

**Images**
An image is like a blueprint. It contains everything needed to run an application.

**Portability**
One of the biggest advantages is that the same container can run on any system without changes.

## Realization

Today it clicked why containers are used everywhere in DevOps. They remove environment issues and make deployments consistent. Instead of worrying about system setup, I can focus on the application itself.

## Summary

Today I learned the basics of containers and Docker. This is a major step because containers are used in modern deployments and connect directly with CI/CD and cloud environments.
