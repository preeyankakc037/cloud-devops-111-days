# Day 108 – Terraform Modules & Reusable Infrastructure Design

## Overview

Today I learned about Terraform modules and how they help structure infrastructure in a reusable and scalable way. After understanding state management, I wanted to move toward writing cleaner and production-level Terraform code.

## My Understanding

I realized that writing everything in a single Terraform file is not practical for real projects. As infrastructure grows, code becomes hard to manage and reuse.

Terraform modules solve this by allowing us to:

* Break infrastructure into smaller components
* Reuse configurations across environments
* Maintain cleaner and organized code

## What I Did

I explored how to create a basic module and how to call it from a main configuration file. I understood how variables and outputs are used to pass values between modules.

I also looked at how modules can represent real components like:

* VPC
* EC2 setup
* Networking
* Storage

## Key Concepts

**Module**
A reusable block of Terraform code that defines infrastructure.

**Root Module**
The main configuration that calls other modules.

**Child Module**
Reusable modules that are called by the root module.

**Input Variables**
Used to pass values into modules.

**Outputs**
Used to return values from modules.

## Example Structure

```
project/
  main.tf
  variables.tf
  modules/
    vpc/
      main.tf
      variables.tf
    ec2/
      main.tf
```

## Key Insight

Modules bring **software engineering practices into infrastructure**:

* Reusability
* Maintainability
* Scalability
